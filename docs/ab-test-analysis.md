# A/B-анализ: ранжирование по ожидаемой комиссии

**Тест:** `revenue_objective` против `production` (SERP-ранкер)
**Дата анализа:** 2026-10-25 · **Источник:** `reports/experiment.json` (seed-набор зафиксирован в `src/experiment.py:73-92`)
**Статус:** анализ завершён, решение принято
**Проверка:** `scripts/verify_ab_readout.py` — 28/28 чисел воспроизведены с точностью 1e-6; закреплено тестом `tests/test_ab_readout_reproducible.py`

---

## Гипотеза

**Что меняется:** порядок выдачи на странице результатов — с логированного порядка (`production`) на сортировку по ожидаемой комиссии партнёра (`revenue_objective`). Обе политики читают один и тот же наблюдаемый набор признаков (`logged`: цена, тип партнёра, позиция); оракульная информация не используется.
**Ожидаемый эффект:** рост выручки на поиск за счёт более дорогих офферов сверху.
**Обоснование:** офлайн-пара `ctr_objective` → `revenue_objective` даёт +34.45% выручки на поиск ценой −16.84% CTR (`reports/headline.json`).

## Дизайн

| Параметр | Значение |
|---|---|
| Сплит | 90/10 (плановый `test_share = 0.1`) |
| Единица рандомизации | `user_id` (кластер анализа — тоже пользователь) |
| Первичная метрика | выручка на поиск = `sum(commission) / count(distinct search_id)` — **ratio-метрика** |
| Guardrails | CTR, конверсия поиска в бронь, средняя цена топ-5, доля офферов выше медианы SERP |
| MDE при плановом размере | 5% относительных (только для сайзинга) |
| Требуемый размер | 91 396 пользователей при 90/10 (82 257 контроль / 9 140 тест) |
| α / power | 0.05 / 0.80 |
| Оценка | дельта-метод, дисперсия кластеризована по `user_id` |
| Правило остановки | guardrail хуже 10% в вредную сторону **и** значим на 5% |

Тест проведён на удержанной половине поисков (модель обучена на другой половине), 6 000 поисков, 3 491 пользователь.

## Решение

**Вердикт: `do_not_ship`** — причина `guardrail breach: ctr, booking_conversion`.

**Обоснование.** Выручка не значимо ниже (−14.26%, CI накрывает ноль), но на этом размере тест её и не мог различить (MDE 15.57%). Решение держится не на первичной метрике, а на guardrails: CTR и конверсия в бронь значимо хуже, точка оценки хуже порога 10%, и обе остаются значимыми после поправки на множественность. Выигрышная первичная метрика при деградировавших guardrails не была бы победой — здесь проигрышны обе.

**Следующие шаги:**
1. Оставить `production` и guardrail-правило как есть — оно отработало в первом же прогоне.
2. Не менять цель, добавить признаки: цена относительно медианы маршрута, история партнёра, глубина просмотра (`production` — бленд истинной релевантности и истинной выручки, у обучаемых политик этих величин нет).
3. Планировать размер заранее: наблюдаемый эффект требует 2 079 пользователей на руку при 50/50 или 10 395 / 1 155 при 90/10.
